TSUGU Workflow / 新規案件登録ガイド

取り扱い説明書

目的、作業、確認結果を一つの案件で管理します。まず案件を作成し、作業分類 → WorkBox → Task の順に作業を組み立てます。JSONでまとめて準備することもできます。

接続 · 画面から登録 · JSON一括取り込み · JSONの書き方 · 登録後の進め方 · 困ったとき

1. GitHubへ接続する

  1. 工程管理ページの「GitHubに接続」を開きます。
  2. 保存先の Owner、Private Repository、Branch を入力します。初期表示は kj2whvbzjn-hue / tsugu-data / main です。利用する保存先を確認してください。
  3. 保存先リポジトリの Contents に読み書きできる Fine-grained PAT を入力し、「接続」を押します。指定したブランチはあらかじめ存在する必要があります。

接続中のアカウント名と保存先が表示されたら利用できます。PATはこのタブを利用している間だけ保持します。再読込した場合は再接続してください。PATを案件の本文やJSONに記入しないでください。

この説明書とサンプルは接続せずに閲覧できます。

2. 画面から新規案件を登録する

  1. 案件一覧の「＋ 新規案件」を押し、案件名を入力して「作成」を押します。
  2. 「概要」の「目的と背景」から「編集」を開き、目的・概要・現在の目標を記入します。
  3. 「構成」で「＋ 作業分類」を追加します。作業分類は親を指定して階層化できます。
  4. 「＋ WorkBox」で所属する作業分類と作業のまとまりを登録します。
  5. 「＋ Task」で所属WorkBox・作業名・受入条件・種別・実行順序を登録します。先に終えるTaskがあれば、そのIDを依存先に指定します。
  6. 「GitHubへ保存」を押し、「GitHubへ保存しました」と版番号が表示されたことを確認します。

通常の「作成」「変更を反映」だけでは保存されません。画面に「未保存」があるときは、移動・再読込の前に保存してください。JSON一括取り込みの「GitHubへ登録」は直接保存します。

3. JSONで新規案件を一括登録する

サンプルJSONをダウンロード（2案件）

  1. サンプルの案件名・目的・作業内容を編集し、UTF-8の .json ファイルに保存します。1案件だけなら projects の2件目を削除します。
  2. GitHubへ接続し、案件一覧の「JSON一括取り込み」を押します。
  3. ファイルを選択するか、「新規登録用JSON」に本文を貼り付けます。ファイル選択後も本文を編集できます。
  4. 「取り込み内容を確認」を押します。全案件の形式・ID・参照先・循環依存を検証します。不正な案件があれば、この段階では何も保存しません。
  5. 案件名・件数・目的を確認します。「登録内容をすべて確認」で省略値を補った内容を確認できます。修正する場合は閉じ、元のJSONを直してやり直します。
  6. 「○案件をGitHubへ登録」を押します。処理中はタブを閉じたり再読込したりせず、完了を待ちます。
  7. 各案件が「登録済み」になったことを確認し、「登録結果JSONを保存」で案件IDと保存commitを控えます。閉じると案件一覧から開けます。

1回につき最大20案件、入力は2MBまで、1案件の記録は合計1000件までです。展開後の保存サイズにも上限があります。大きい場合は案件・内容を分けてください。

各案件に新しい案件IDを発行します。既存案件の上書き・更新・重複排除は行いません。同じJSONを再登録すると別案件になります。すべて「検討」工程・Activeで開始し、TaskはTodo、承認と確認はPendingです。

複数案件を一つの取引として保存する機能ではありません。順番に保存し、失敗した案件で停止します。先に登録された案件は残ります。結果の「要確認」「未登録」の扱いは困ったときを参照してください。

4. JSONの書き方

最小形式です。案件名だけでも登録できます。コメントや末尾の余分なカンマは使えません。

{
  "schema_version": "tsugu-project-import/1",
  "projects": [
    { "name": "新しい案件", "project_context": { "purpose": "この案件で達成したいこと" } }
  ]
}

projectsは案件の配列です。同じJSON内では案件名を重複させないでください。各記録には英数字・ハイフン・アンダースコア・ピリオドで id を指定します。同一案件の同じ種類の中でIDは一意にします。別案件では同じIDを使えます。

取り込み形式の使い分け

  • 新規案件登録：この説明書の tsugu-project-import/1 を使用します。
  • 既存案件へ内容を追加・更新：「引継ぎ」→「AI返却JSONを確認」を使用します。project_id・instance_id・base_revision が一致する案件だけに統合します。
  • 「案件JSONを保存」で出力したファイル：tsugu-workflow/1 の案件記録です。この新規登録フォームには直接戻せません。新規案件として利用する場合は、name と計画に必要な配列だけを上記形式へ移してください。
  • 旧システムのJSON：items / core などの自動変換はありません。上記の作業分類・WorkBox・Taskへ整理してください。

authority、workspace、revision（案件直下）、workflow、lifecycle、history、各承認、確認の実施結果・証拠、実装記録・成果物・イベント履歴は新規取り込みでは受け付けません。実績を新規案件の承認として流用しないためです。

5. 登録後に工程を進める

  1. 検討：目的と作業計画を整え、「工程・確認」から「実装準備へ」を押します。
  2. 実装準備：Implementationの確認事項を1件以上登録し、実施して結果・証拠を記録します。確認が成立したら「実装開始を承認」を押します。
  3. 実装：承認が必要なTaskは「Taskを承認」を押します。依存先が完了していれば「開始」できます。作業後はTask対象・Completionの確認事項を実施し、結果・証拠を記録します。SOURCE_UPDATE / GAME_DATAは「実装・成果物」でAppliedの実装記録と40桁のcommit SHAも記録します。
  4. 確認：Taskをすべて完了し、「確認工程へ」を押します。Completionの確認事項、必須FAIL、未解決の変更影響を確認します。
  5. 完了：条件がそろったら「完了を承認」を押します。変更を「GitHubへ保存」します。

Failedの記録は変更・削除しません。再確認の記録を追加し、「解決するFailed Check ID」に元のIDを指定します。対象と工程が同じ再確認で解決します。計画変更で承認対象が変わった場合は承認が無効になり、再確認が必要になります。

6. 困ったとき

表示・状況対応
JSONの構文が不正キーと文字列を半角の二重引用符で囲み、コメント・末尾のカンマ・Markdownのコード囲みを取り除きます。
未対応の案件形式／項目schema_version と取り込み用途を確認します。エクスポート記録やAI返却を直接貼らないでください。エラーに出た項目名を確認します。
参照先が存在しない／循環依存／ID重複node_id・box_id・depends_onなどを確認します。参照先を同じ案件へ追加し、IDの大文字・小文字も一致させます。相互に依存するTaskは分割します。
取り込み結果が「要確認」その案件で処理を停止しました。保存が成功した後に応答だけ失われた可能性もあります。登録結果JSONを保存し、閉じて「再読込」を押します。結果JSONの案件IDを一覧のファイル名と照合し、開いて内容を確認してください。必要なら保存先の記載パスをGitHubでも確認します。存在しないことが確認できるまで再登録しません。
取り込み結果が「未登録」その案件は保存処理を開始していません。元JSONのprojectsから登録済み・要確認の案件を除き、未登録だけを再取り込みできます。
途中でタブを閉じた／結果を控え忘れた再接続して案件一覧を再読込します。案件名と内容を確認し、必要なら保存先の更新履歴を確認してください。登録済み案件を重複作成しないよう、元JSONを全件再送しないでください。
GitHub HTTP 403 / 404アカウント・PATの対象リポジトリと書込権限、Owner・Repository・Branch、リポジトリがPrivateであることを確認します。
競合／再読込が必要別タブや他の担当者が更新した可能性があります。未保存内容が必要なら「案件JSONを保存」で控えてから最新を再読込し、変更を見直します。
